Отчёт Казаковай Айдай по лабораторной работе GitHub Actions
## Контрольные вопросы

1. Из чего состоит workflow:
Workflow — это весь наш файл автоматизации. Он срабатывает на событие (например, push). Внутри него есть jobs (работы), а внутри каждой работы идут steps (пошаговые шаги), которые выполняют конкретные команды или скрипты.

2. Чем job отличается от step:
Job — это отдельный виртуальный сервер (компьютер), который выдает GitHub. Разные jobs работают независимо друг от друга. А steps — это просто команды по очереди внутри этого одного компьютера.

3. Чем push отличается от workflow_dispatch:push запускает проверку сам, как только мы отправляем код в репозиторий. A workflow_dispatch — это кнопка «Run workflow» на сайте GitHub, чтобы запустить процесс вручную, когда захочется.

4. Как безопасно передать пароль или токен:
Сохранить его в настройках репозитория на GitHub в разделе Secrets. В коде воркфлоу к нему обращаются через ${{ secrets.ИМЯ_СЕКРЕТА }}, и GitHub сам прячет его в логах за звездочками (***).

5. Что такое артефакт и зачем он нужен:
Это файл, который создался во время работы воркфлоу и сохранился на GitHub. Он нужен, чтобы передать файл с одной изолированной машины на другую (через upload/download) или чтобы скачать готовый результат сборки себе на ПК.

6. Как дождаться другого job и зачем линтер, если есть тесты:
Чтобы один job ждал другой, используют строчку needs: имя_джобы.
Линтер нужен для того, чтобы быстро проверить сам текст кода на опечатки и плохой стиль, даже не запуская его. А тесты проверяют, как программа работает по логике. Линтер срабатывает быстрее и помогает держать код чистым.
